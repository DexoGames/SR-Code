What these results do—and do not—show
The tests rasterize generated codes, alter their pixels, then run the same reader used here. They do not extract payloads from SVG metadata. Each cell reports successful reads out of the tested messages.
Cover percentages refer to a square mask within the data area. Damage position matters: recovery requires enough reference geometry and sufficient surviving codewords in every block. Three reference marks can support recovery; more improve alignment.
This is synthetic testing, not physical camera or printer validation. Glare, curved surfaces, focus, screen moiré and severe perspective need real-world trials. A camera interface is included, but no physical-camera performance is claimed.

        
RS Code format and QR feature coverage
Implemented: UTF-8 text and arbitrary bytes, four sizes, four Reed–Solomon protection levels, erasure recovery, byte interleaving, checksums, format identification, rotation/reflection handling, perspective registration, inverted colours, cropping recovery where reference geometry survives, and structured append up to 16 parts.
RS Code is not ISO QR Code and does not scan in ordinary QR readers. QR-specific numeric/alphanumeric/Kanji compression, ECI and GS1/FNC1 modes are not implemented. UTF-8 and binary carry the content without those specialised compression conventions. Curved-surface recovery and guarantees for arbitrary missing regions are outside this prototype.
